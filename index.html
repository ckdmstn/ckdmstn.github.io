소개

Java와 Spring Boot로 백엔드를 개발합니다. 2023년 한이음 프로젝트에서 스터디 모집부터 관리까지 한 곳에서 해결하는 웹 플랫폼 StarD의 백엔드를 맡았고, 이 프로젝트로 교내 소프트웨어 경진대회에서 우수상을 받았습니다.

개발하면서 '동작하는 것'과 '정확한 것'이 다르다는 걸 여러 번 겪었습니다. 관심분야 하나를 지웠는데 회원 정보 전체가 삭제되던 cascade 버그, 참여자가 한쪽에 몰리면 추천 결과가 쏠리던 장소 추천 로직처럼 겉으로는 잘 동작하지만 실제로는 틀린 결과를 내는 문제를 원인까지 확인해 고쳤습니다. 코드를 짤 때도 정답이 나왔다고 바로 넘기지 않고, 불필요하게 반복되는 부분이나 자원을 과하게 쓰는 부분이 없는지 다시 점검합니다.

현재는 SSAFY에서 Java, 알고리즘, AI 등의 과정을 배우고 있으며, Claude, Claude Code 같은 AI 도구를 활용해 개발한 경험이 있습니다.

해결한 문제

관심분야를 삭제했더니 회원 정보가 함께 삭제된 문제
상황
회원의 관심분야 하나를 삭제하면 해당 회원 정보 전체가 함께 삭제됐습니다. 자료마다 설명이 달라 며칠을 헤맸고, JPA의 cascade와 orphanRemoval 옵션을 바꿔봐도 회원이 삭제되지 않는 대신 다른 문제가 생기는 식으로 문제가 자리만 옮겨 다녔습니다.
원인
옵션을 하나씩 바꾸며 결과를 직접 확인한 끝에, 관심분야 엔티티에서 회원을 참조하는 @ManyToOne에 걸어둔 cascade ALL이 삭제 이벤트를 회원 엔티티까지 전파하고 있다는 걸 찾았습니다.
해결
옵션을 제거해 해결했습니다. 이후에는 연관관계를 설정할 때 한쪽의 변경이 반대편 데이터에 어떤 영향을 주는지부터 확인합니다.
장소 추천 결과가 한쪽으로 쏠리는 문제
상황
참여자 위치의 중간 지점을 추천하는 기능을 처음에는 좌표의 단순 평균으로 구현했는데, 참여자가 한쪽 지역에 몰려 있으면 추천 결과도 그쪽으로 쏠렸습니다.
원인
같은 지역에 몰린 사용자들이 결과에 여러 번 반영되는 구조였습니다.
해결
볼록 껍질(Convex Hull)과 그라함 스캔으로 좌표의 외곽선만 추출하고, 외곽 좌표로 균형점을 계산하도록 바꿨습니다. 참여자 위치를 일부러 한쪽에 몰아 테스트해 결과가 더 이상 쏠리지 않는 걸 확인했습니다.
팀블로그 파일 첨부 수정 방식 개선
상황
게시글에는 파일을 최대 5개까지 첨부할 수 있었고, 수정할 때 기존 파일 유지, 일부 삭제, 새 파일 추가, 삭제와 추가 동시 진행이 한 번의 요청에 섞여 있었습니다. 처음에는 수정할 때마다 기존 파일을 전부 지우고 새로 받은 파일을 다시 저장했는데, 글 내용만 고쳐도 파일이 매번 다시 올라간다는 팀원의 지적이 있었습니다.
해결
삭제할 파일의 ID 목록과 새로 추가할 파일만 서버로 보내 변경분만 처리하도록 바꿨습니다. 최대 5개 제한은 기존, 삭제, 추가 파일 수를 모두 계산해 검증했습니다.

AI 경험

SSAFY AI 챌린지

2026.09.21 – 2026.09.23 (3일)

개요

  • 과제: 이미지 기반 객관식 VQA(Visual Question Answering). 사진과 질문이 주어지면 a/b/c/d 중 하나를 선택, 테스트 6,714건
  • 참여 방식: 5인 팀이지만 각자 개인으로 진행했고, 그중 가장 높은 점수가 팀 점수가 됨. 이 작업은 개인 작업이며 Claude와 함께 진행. 팀 내 최고 점수는 다른 팀원의 기록
  • 환경: 로컬 데스크탑 RTX 5060 Ti(VRAM 16GB), Python, PyTorch. 대회 규정상 오프라인 실행. Qwen2.5-VL 계열 모델을 4bit 양자화(QLoRA)로 파인튜닝

점수 변화

검증 정확도는 학습 데이터에서 분리한 300건 기준
단계검증 정확도제출 점수
베이스라인 (3B, 학습 200건)측정 안 함0.70122
1차 개선 (3B, 학습 1,500건)0.85330.87101
7B 모델로 교체, 학습 전0.9067-
7B + 학습 3,000건 (최종 채택)0.92670.91837
7B + 2,300건 추가 학습 (미채택)0.9233-

개선 내용 (Claude와 함께 진행)

  • 손실 마스킹: 베이스라인은 시스템 프롬프트, 질문, 선지, 이미지 토큰 전체에 loss가 걸려 정답 한 글자의 비중이 매우 작았음. 패딩과 마지막 정답 턴 이전 구간을 -100으로 마스킹해 정답 토큰에만 loss가 걸리게 수정. 효과가 가장 컸던 수정
  • 모델 교체와 데이터 확대: 베이스 모델 3B → 7B, 학습 데이터 200건 → 1,500건 → 3,000건. 학습하지 않은 7B(0.9067)가 1,500건 학습한 3B(0.8533)보다 높았음
  • 추론 방식 변경: 텍스트 생성 후 파싱하던 방식 대신 a/b/c/d 네 토큰의 확률만 비교. 선지 순서를 4가지로 순환해 확률을 합산하는 TTA로 위치 편향 완화
  • 추론 중단 복구: 약 4시간짜리 추론이 65%에서 소실된 뒤, 20건마다 중간 결과를 저장하고 이어서 실행되도록 변경

판단 사례

  • 검증 정확도가 제출 점수와 근접하다는 것을 확인한 뒤, 3~4시간 걸리는 전체 추론을 돌리기 전에 검증 정확도로 개선 여부를 먼저 판단
  • 추가 학습 2,300건은 검증 정확도가 0.9267 → 0.9233으로 소폭 하락해 채택하지 않음
